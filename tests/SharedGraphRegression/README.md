# 共有グラフの回帰検査

.NET 10 SDKで次のコマンドを実行する。

```sh
dotnet run --project tests/SharedGraphRegression/SharedGraphRegression.csproj --configuration Release
```

本番の共有更新状態管理、タブ、エディター、ライブラリのソースを直接リンクする。YMM4、WPFのDispatcher、描画グラフ、エディター内部の表示部分はHostStubs.csへ置き換える。したがって、この検査はWindows上のコントロール操作やDirect2D描画を検証するものではない。JSONの検査には.NET SDKに同梱されたNewtonsoft.Jsonを使用する。本番のYMM4プロジェクト保存形式とは区別する。

検査対象は、切替時の保留更新破棄、別IDからの遅延更新拒否、最新更新の採用、非同期保存の世代検査、保留更新中の旧状態の保存拒否、タブ再利用時の改名購読切替、タブ破棄時の購読解除、共有更新によるタブ選択・再表示の抑止、削除後の同一エントリー復元、共有先と配信元の分離、同名グラフの識別、並替のJSON保存復元、複製後のスナップショット置換の独立性である。加えて、Roslynで本番C#ソースの構文を検査する。構文検査は本番プラグインの型検査・ビルドの代用にはならない。

## Windows / YMM4での確認事項

| 操作 | 期待結果 |
| --- | --- |
| Aを開いてBへ切替後、AとBをそれぞれ改名する | タブとコンボボックスはBに追従し、Aの改名に反応しない |
| 同じ共有グラフの2タブの一方でノードを追加・削除する | 再生停止中でも他方の表示へ反映され、選択中タブが変わらない |
| 共有先に保留更新がある状態で別グラフへ切り替える | 切替前の更新が切替後へ混入しない |
| 共有更新直後に共有先を編集する | 古いライブグラフが共有元へ書き戻されない |
| グラフを切替後、Undo / Redoする | GraphIdとコンボボックス選択が一致する |
| 参照中のグラフを削除し、参照元で編集して復元後に改名する | 実行中の名称・ID・タブの改名購読が保持される |
| タブを閉じた後で共有更新を受信する | 閉じたタブが自動で開かない |
| エディターを何度も開閉し、エフェクトの選択を変える | 通知・ショートカットが重複せず、解除後のコントロールに通知しない |
| グラフを複製し、別々に編集してプロジェクトを保存・再読込する | ID、名前、配線、各エフェクトの引数が保持される |

プロジェクト切替時にYMM4がツールViewModelを再生成するかどうかは、この検査では確認しない。ライブラリのプロジェクト境界、削除情報のプロセスをまたいだ保持、64スロットのYMM4保存復元・再割当は別の検証対象である。
